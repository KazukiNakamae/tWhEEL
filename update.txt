# tWhEEL アップデート情報
# Version 1.0.0 → 1.0.1
# 更新日: 2025年12月8日

================================================================================
## 概要
================================================================================

tWhEEL v1.0.1では、既存のアミノ酸配列ファイルを直接使用する機能追加と、
出力ディレクトリ構造の整理を行いました。これにより、処理の柔軟性と
プロジェクト管理の効率性が大幅に向上しています。

================================================================================
## 主要な新機能・改善点
================================================================================

### 1. 既存アミノ酸配列ファイル使用機能 [NEW]

**概要**
- 既にORF予測が完了したアミノ酸配列ファイルを直接使用可能
- TransDecoder処理を自動的にスキップして処理時間を短縮
- 2つの入力モードに対応（TransDecoder/既存タンパク質）

**利点**
- 処理時間の大幅短縮（数時間→数分）
- 既存のキュレートされたタンパク質データセットの活用
- 異なるORF予測ツールの結果との比較解析が容易
- リソース使用量の最適化

### 2. 出力ディレクトリ構造の整理 [IMPROVED]

**概要**
- TransDecoder作業ファイルの専用ディレクトリ化
- プロジェクトルートディレクトリの清潔性維持
- 中間ファイルの一元管理

**新しい出力構造**
```
outputs/tWhEEL_on_[timestamp]_[analysis]/
├── intermediate/
│   ├── transdecoder_output/          # TransDecoder専用ディレクトリ
│   ├── busco_output/                 # BUSCO結果
│   ├── multi_genes/                  # Multi遺伝子ファイル
│   ├── multi_genes_aligned/          # アライメント済みファイル
│   └── (その他中間ファイル)
├── web_data/
├── report.html
└── summary.txt
```

## 詳細変更内容
================================================================================

### 設定ファイル変更 (config/default.yaml)

**追加された設定項目**
```yaml
input:
  protein_sequences: ""  # 既存のアミノ酸配列ファイル（新規追加）
  transcriptome: ""      # コメント更新: protein_sequencesが未指定の場合のみ必須

transdecoder:
  skip_if_protein_provided: true  # 新規オプション
```

### 新設定ファイル (config/example_existing_protein.yaml) [NEW]

既存タンパク質モード用の完全な設定例ファイルを新規作成。
詳細なコメントと使用例を含む。

**改良メソッド**
- `run_transdecoder()`: 専用作業ディレクトリでの処理
- `run()`: 入力モード対応の条件分岐実装

**出力ディレクトリ改善**
- TransDecoder専用ディレクトリ: `intermediate/transdecoder_output/`

- `run_fasta_search()`: 作業ディレクトリの整理

**Dockerマウント改善**
- intermediate_dirを基準とした処理
- ファイル散乱の防止

#### twheel.py の主要変更

**改良メソッド**
- `validate_inputs()`: 新入力モード対応の検証ロジック

**更新セクション**

## 使用方法
================================================================================

### 従来通りの使用方法（TransDecoderモード）
```bash
# 設定ファイルでtranscriptomeを指定
python src/twheel.py --config config/default.yaml --name my_analysis
```

### 新機能: 既存タンパク質モード
```bash
# 設定ファイルでprotein_sequencesを指定
python src/twheel.py --config config/example_existing_protein.yaml --name protein_analysis
```

### 設定例：既存タンパク質モード
```yaml
input:
  protein_sequences: "/path/to/existing_proteins.fasta"  # 既存タンパク質配列
  uniprot_db: "/path/to/uniprot_sprot.fasta"
  genome_assembly: "/path/to/genome.fasta"              # オプション

transdecoder:
  skip_if_protein_provided: true  # 自動スキップ
```

## 既知の制限・注意事項

### 制限事項
- genome_assembly未指定時のオフターゲット解析精度は依然として限定的
- 大容量データセットでは十分なメモリとディスク容量が必要

### 重要な変更点（v1.0.1後期修正）
- **transcriptomeファイルは常に必須**: tWhEELはトランスクリプトームベースパイプラインのため
- **既存タンパク質モードでも転写産物情報を活用**: ガイドRNA設計等で転写産物データを使用
- **入力検証の強化**: transcriptome未指定時はエラーで停止するように改善
================================================================================

### 制限事項
- 既存タンパク質モードでは転写産物レベルの情報は利用不可
- genome_assembly未指定時のオフターゲット解析精度は依然として限定的

### 注意事項
- 既存タンパク質ファイルの形式はFASTA形式である必要があります
- ファイルサイズが大きい場合は十分なディスク容量を確保してください
- 複数解析の並行実行時は出力ディレクトリ名の重複にご注意ください
