tWhEEL historical implementation note: existing protein input
================================================================

This file replaces an older, internally inconsistent v1.0.1 update note. Git
does not contain a v1.0.1 tag, so this document is not release-version
authority. See LOG.md for tagged history and README.md for current usage.

Feature summary
---------------

tWhEEL can use an existing amino-acid FASTA instead of running TransDecoder.
The transcriptome remains mandatory because transcript-sequence extraction,
multi-group alignment, and guide design still use transcript data.

The effective mode is determined as follows:

- existing protein mode: `input.protein_sequences` names an existing file and
  `transdecoder.skip_if_protein_provided` is true;
- TransDecoder mode: all other cases.

`skip_if_protein_provided` defaults to true when omitted.

Current configuration
---------------------

```yaml
input:
  transcriptome: "/path/to/transcripts.fasta"
  protein_sequences: "/path/to/proteins.fasta"
  protein_transcript_mapping: "/path/to/mapping.tsv"
  protein_db_for_goanalysis: "/path/to/uniprot_sprot.fasta"
  genome_assembly: "/path/to/genome.fasta"  # optional

transdecoder:
  skip_if_protein_provided: true
```

The implemented GO database key is `protein_db_for_goanalysis`. The legacy
name `uniprot_db` is not read.

Mapping file contract
---------------------

The mapping is a headerless, tab-delimited file:

```text
transcript_id<TAB>protein_id
```

Blank lines and lines beginning with `#` are ignored. Extra columns are
ignored. A normal header row is not detected and would be treated as data.

Processing behavior
-------------------

In both input modes, `gene_prediction`:

1. copies or decompresses the transcriptome to `intermediate/transcriptome.fa`;
2. copies supplied proteins or runs TransDecoder to produce
   `intermediate/query.pep`;
3. collects SeqKit statistics; and
4. runs BUSCO on `query.pep`.

When existing protein mode is effective, `annotation` and `sgd_annotation`
require the mapping file. They use it to resolve protein query identifiers to
transcript identifiers before extracting downstream nucleotide sequences.

Output layout
-------------

TransDecoder work, when needed, is kept under
`intermediate/transdecoder_output/`. Prepared transcript and protein FASTA
files, BUSCO output, annotation artifacts, guide tables, and step result notes
remain under the run's `intermediate/` directory. Reports and their `static/`
and `web_data/` resources are written at the run level.

Current limitations
-------------------

- The supplied protein FASTA and mapping TSV identifiers must agree exactly.
- Missing protein mappings are excluded from standard annotation grouping.
- A configured but missing protein FASTA selects TransDecoder mode rather than
  existing protein mode.
- Omitting the genome assembly makes guide design use the transcriptome as a
  less comprehensive off-target reference.
- Docker and relevant network services remain required in existing protein
  mode; only the TransDecoder invocation is omitted. BUSCO, annotation, guide
  design, and selected report/GO services still run.
